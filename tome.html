R2 keys come from an API token: Cloudflare dashboard → R2 → Manage R2 API Tokens → Create API token (permission Object Read, or Object Read & Write for your sync source). Cloudflare shows the Access Key ID and Secret Access Key once; paste them below. Your Account ID is on the R2 overview page.

Use an app password, not your login password: in Nextcloud open your avatar → Personal settings → Security → Devices & sessions → Create new app password. For the address, paste your Nextcloud address (or any page of it from the browser), or the WebDAV address from Files → Files settings. Your server must allow this page (CORS) — see Nextcloud setup below.

Read-only key & CORS setup

Use a key that can only list and read. Tome streams with signed requests and never creates shareable links. To sync progress between devices, the key for your sync source also needs write access to sync/*.

AWS / Wasabi IAM policy (replace BUCKET):

{ "Version": "2012-10-17", "Statement": [
  { "Effect": "Allow", "Action": ["s3:ListBucket"],
    "Resource": "arn:aws:s3:::BUCKET" },
  { "Effect": "Allow", "Action": ["s3:GetObject"],
    "Resource": "arn:aws:s3:::BUCKET/*" },
  { "Effect": "Allow", "Action": ["s3:PutObject"],
    "Resource": "arn:aws:s3:::BUCKET/sync/*" } ] }

Cloudflare R2: create an API token with Object Read (add Object Read & Write only if this is your sync source).

Bucket CORS (all providers). Streaming and seeking need Content-Range exposed:

[{ "AllowedOrigins": ["https://YOU.github.io"],
   "AllowedMethods": ["GET", "HEAD", "PUT"],
   "AllowedHeaders": ["*"],
   "ExposeHeaders": ["Content-Range", "Content-Length",
                     "Accept-Ranges", "ETag"],
   "MaxAgeSeconds": 3600 }]

WebDAV: use an app password or a read-only account where your server supports it. The server must answer CORS for this page, including the PROPFIND method. Example for an nginx reverse proxy:

add_header Access-Control-Allow-Origin "https://YOU.github.io" always;
add_header Access-Control-Allow-Methods "GET, HEAD, PUT, PROPFIND, MKCOL, OPTIONS" always;
add_header Access-Control-Allow-Headers "Authorization, Depth, Range, Content-Type" always;
add_header Access-Control-Expose-Headers "Content-Range, Content-Length, Accept-Ranges, ETag" always;
if ($request_method = OPTIONS) { return 204; }

Nextcloud setup. Nextcloud doesn't send CORS headers for WebDAV, so the web server in front of it has to. Allow your Tome address and answer the browser's OPTIONS check before Nextcloud asks for a password. Apache (in the Nextcloud virtual host, needs mod_headers and mod_rewrite):

<Location /remote.php/dav/>
  Header always set Access-Control-Allow-Origin "https://YOU.github.io"
  Header always set Access-Control-Allow-Methods "GET, HEAD, PUT, PROPFIND, MKCOL, OPTIONS"
  Header always set Access-Control-Allow-Headers "Authorization, Depth, Range, Content-Type"
  Header always set Access-Control-Expose-Headers "Content-Range, Content-Length, Accept-Ranges, ETag"
</Location>
RewriteEngine On
RewriteCond %{REQUEST_METHOD} OPTIONS
RewriteRule ^/remote\.php/dav/ - [R=204,L]

For nginx, add the WebDAV lines above to the location that serves /remote.php. App passwords can't be limited to reading; Tome only reads, plus sync/ on your sync source and covers/metadata if you allow writes.
